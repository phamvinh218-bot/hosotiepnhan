## Project overview

DuHoc24 — a sample/teaching website for a study-abroad application intake service ("Cổng Tiếp Nhận Hồ Sơ Du Học"), built for a 6-week course. This is **Week 1**: UI only, all data is hardcoded mock data in [`lib/mock-data.ts`](lib/mock-data.ts). There is no backend, API, or database yet — later weeks (documented in [README.md](README.md)) progressively add Gemini API, Supabase, file processing, Make.com automation, and Supabase Auth. When asked to implement a later-week feature, check the README's week-by-week checklist to see what's expected and what's intentionally still missing.

All UI copy and content is in Vietnamese — keep new copy consistent with that.

## Architecture

- **Next.js 16 (App Router) + React 19 + TypeScript**, Tailwind CSS v4, shadcn/ui (style `base-nova`, on Base UI, see [components.json](components.json)).
- This Next.js version has breaking changes vs. training data — **AGENTS.md (imported above) requires reading `node_modules/next/dist/docs/` before writing any Next.js–specific code** (routing, layouts, data fetching, config, etc.). That block is auto-regenerated by `next dev`; don't strip it from commits.
- **Two independent route trees** under `app/`:
  - Public site: `/` (landing page: hero, quote form, chatbot widget UI, highlights, footer) and `/portal` (student document upload/status UI). No shared layout beyond the root `app/layout.tsx`.
  - Admin: `app/admin/*` shares `app/admin/layout.tsx`, which renders `AdminSidebar`/`AdminMobileNav` ([components/admin/sidebar.tsx](components/admin/sidebar.tsx)) around each page. `/admin` itself just redirects to `/admin/requests`. Sub-routes: `requests`, `schools`, `profiles`, `conversations` — each a read-only table/list view over mock data.
- **All domain data and types live in [`lib/mock-data.ts`](lib/mock-data.ts)**: `School`, `AdmissionRequest`, `StudentProfile`, `Conversation`/`ChatMessage`, `ServiceOption`, plus status union types (`DocStatus`, `RequestStatus`, `ServicePackage`). Pages import directly from here instead of fetching — when wiring up real data later, this is the module to replace/back with Supabase queries, keeping the same shapes where practical.
- **Components** are split by area: `components/landing/*` (public landing sections), `components/portal/*` (student portal sections), `components/admin/*` (sidebar/header for admin), and `components/ui/*` (shadcn primitives — regenerate/add via `npx shadcn add <component>`, don't hand-roll edits that fight the generator's structure). `components/status-badge.tsx`, `components/logo.tsx`, `components/site-header.tsx`, `components/site-footer.tsx` are shared across both trees.
- `lib/utils.ts` has only the shadcn `cn()` classname helper.
- Path alias `@/*` maps to the repo root (see [tsconfig.json](tsconfig.json)); use it instead of relative `../../` imports, matching existing code.
- `.env.example` documents env vars for *future* weeks (Supabase, site URL for magic-link auth) — not required for `npm run dev` today.
